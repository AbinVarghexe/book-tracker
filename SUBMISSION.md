## 2. Five Most Important Prompts

### Prompt 1: Project Scaffolding & Architecture
> *"I want to build a Book Tracker web page using plain HTML, CSS and JavaScript. Features: add a book with title, author and status (To read, Reading, Finished), show the list newest first, search by title or author, change status, and keep the data after a refresh. Before writing any code, list the files you will create and explain how the data will be saved."*

**Outcome:** Established the project blueprint, file separation (`index.html`, `styles.css`, `app.js`), `localStorage` schema (`book_tracker_books_v1`), and responsive two-column layout.

---

### Prompt 2: Core Form Validation & Newest-First List Ordering
> *"Create the book entry form with Title, Author and a Status dropdown (To read, Reading, Finished). When I click Add, show the book at the top of a list. Title and Author are strictly required. If one is empty, show a message under that box: 'Please enter a title' and 'Please enter an author'. Clear the error message as soon as the user starts typing."*

**Outcome:** Built form submission logic with defensive input checking, field-specific inline error containers, real-time input clearing, and `books.unshift()` to guarantee newest-first chronological rendering.

---

### Prompt 3: Data Persistence with LocalStorage
> *"Save the book list in localStorage so all books and their updated statuses persist after a page refresh. Load the saved list when the page opens, and provide sample seed data for first-time visitors."*

**Outcome:** Integrated `loadBooks()` and `saveBooks()` wrappers with error handling, ensuring initial sample books (e.g., *"Aadujeevitham" by Benyamin*) are visible immediately and changes persist across tab closes and page reloads.

---

### Prompt 4: Case-Insensitive Search & Status Filtering
> *"Add a search box above the list. As I type, show only books whose title or author contains the search text, ignoring capital letters (for example, typing 'ben' or 'BEN' should match 'Benyamin'). Also add status filter tabs (All, To read, Reading, Finished)."*

**Outcome:** Implemented combined filter logic with `.toLowerCase().trim()`, an instant clear search button (`x`), active pill state management, and clear empty-state messaging when no matches are found.

---

### Prompt 5: Wise Design System Integration & UI Polish

## 3. One Time the AI Got Something Wrong, and How It Was Fixed

### The Problem
During development of the search functionality and status synchronization, the AI initially implemented the search filter with exact string casing:
```javascript
// Initial buggy search code generated by AI
const filteredBooks = books.filter(book => 
  book.title.includes(query) || book.author.includes(query)
);
```

When searching for `"ben"` (lowercase) or `"BEN"` (uppercase), the book *"Aadujeevitham"* by *"Benyamin"* disappeared from the list because `.includes()` performed a case-sensitive check against `"Benyamin"`. 

Additionally, status changes in the dropdown were updating the DOM badge text but were not immediately updating the live counter badges in the header until a manual page refresh was triggered.

### How It Was Identified
I tested the app like a real user with deliberate edge cases:
1. Typed `"ben"` and `"BEN"` into the search box. I expected *"Aadujeevitham" by Benyamin* to remain visible, but the empty state appeared.
2. Changed the status of *"Aadujeevitham"* from *"To read"* to *"Finished"*. The card's badge changed, but the top stats bar still displayed `0 Finished` and `1 To read`.

### How It Was Fixed
I prompted the AI:
> *"When I search for 'ben' or 'BEN', nothing shows even though the book 'Aadujeevitham' by 'Benyamin' is in the list. Also, changing a book's status does not update the count in the top stats bar until I refresh. What is wrong and how do we fix both?"*

The AI corrected both issues in `app.js`:
1. **Case-Insensitive Search:** Normalized both the search query and the book fields with `.toLowerCase().trim()`:
   ```javascript
   const query = currentSearchQuery.toLowerCase().trim();
   const titleMatch = book.title.toLowerCase().includes(query);
   const authorMatch = book.author.toLowerCase().includes(query);
   return titleMatch || authorMatch;
   ```
2. **Synchronous Stats Recalculation:** Centralized `updateStats()` and invoked it inside `renderApp()`, so every status mutation immediately recalculates counts across the top stat cards and filter tab badges before saving to `localStorage`.
